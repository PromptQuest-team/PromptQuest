# PromptQuest

Обучающая веб-игра для тренировки prompt-инжиниринга: игрок видит сцену и цель,
описывает нужный результат, код (в Фазе 1 — вручную) применяется к сцене в
изолированном `iframe`, и автоматический валидатор проверяет, достигнута ли цель.
Дипломная практика.

Полное техническое задание — [`SPEC.md`](SPEC.md), плюс два дополнения:
[`SPEC-ADDENDUM-01.md`](SPEC-ADDENDUM-01.md) (изоляция `goal`/`hint` от ИИ, принцип
формулировки уровней) и [`SPEC-ADDENDUM-02.md`](SPEC-ADDENDUM-02.md) (принцип «скрытой
информации» — решение уровня не должно быть выводимо из одного `scene.html`).

**Статус: Фаза 1 (MVP без БД и без ИИ) реализована полностью** и соответствует всем
18 критериям приёмки раздела 18 SPEC.md плюс критериям 19–22 из обоих дополнений.

## Как запустить

```
dotnet run --project PromptQuest.Web
```

или открыть `PromptQuest.sln` в Visual Studio и нажать F5/Ctrl+F5 — профиль `http`
поднимет браузер на `http://localhost:5280`. Внешних зависимостей, БД или ключей API
не требуется — проект собирается и запускается «в одно нажатие».

Экраны: ввод никнейма → список из 12 уровней → игра (сцена + код + результат
проверок) → таблица лидеров. Подробности игрового цикла — раздел 13 SPEC.md.

## Что реализовано

- ASP.NET Core 9 Minimal API, раздаёт и API, и статику фронтенда из одного процесса.
- Фронтенд на чистом HTML/CSS/JS (ES-модули), без фреймворков и сборщиков.
- Полный движок валидации: sandbox-`iframe` (`sandbox="allow-scripts"`, без
  `allow-same-origin`), протокол `postMessage`, сторожевой таймер, двойной
  `requestAnimationFrame`, все 9 видов проверок из раздела 10 SPEC.md.
- 12 уровней (`css-01`…`css-06`, `sel-01`…`sel-03`, `js-01`…`js-03`) в
  `Data/levels.json`, каждый проверен вручную геометрическим/логическим расчётом
  относительно эталонного решения.
- Режим ручного ввода кода (раздел 14), полностью управляемый флагом
  `ManualCodeEntry` из конфигурации — не зашит статически на фронтенде.
- Расчёт очков на сервере (`ScoreCalculator`), таблицы лидеров по уровню и общая.
- In-memory хранилища за интерфейсами, готовыми к замене на EF Core/SQL в Фазе 2
  без изменения `Endpoints/`, `Dtos/` или `wwwroot/` (раздел 4.4 SPEC.md).
- Уровни `sel-01`, `sel-02`, `js-02` пересмотрены по принципам обоих дополнений:
  сцена не содержит семантически понятных имён (`plate`/`bowl`/`active` и т.п.),
  решение нельзя вывести из одного `scene.html` без `goal`, которое видит только
  игрок (см. историю правок в памяти проекта и коммит-сообщения).

## Известные и исправленные баги этой сессии

- Sandbox-iframe удалялся сразу после прогона — сцена «мигала» и пропадала.
  Исправлено: iframe остаётся на экране до следующего прогона, удаляется только
  при таймауте.
- `runner.js` грузился как ES-модуль (`type="module"`) — в Firefox это ломало
  загрузку из-за CORS-проверки для opaque-origin сэндбокса (Chrome прощал).
  Исправлено переключением на классический `<script>`.
- Устаревший `playerId` в `localStorage` браузера (после перезапуска сервера,
  который стирает in-memory данных Фазы 1) вызывал ошибку «игрок не найден» до
  ручной смены никнейма. Исправлено: `app.js` проверяет `playerId` на сервере при
  старте и сам сбрасывает его, если сервер его не знает.
- Лягушка визуально терялась под кувшинкой (обе — круги одного размера, `z-index`
  каскада ставил `position:absolute`-кувшинку поверх). Исправлено общим стилем в
  `runner.html`: лягушка всегда поверх, кувшинка крупнее и другой формы.

## Что ещё нужно сделать

### Фаза 2 — обязательное для реального продукта

- **База данных.** Сейчас всё в `ConcurrentDictionary` в памяти процесса — данные
  пропадают при каждом перезапуске. Нужно добавить EF Core + провайдер БД, написать
  `SqlPlayerStore`/`SqlAttemptStore` по тем же интерфейсам, продумать индексы для
  `LevelProgress`.
- **Подключение AI API.** `ManualCodeGenerationService` — единственная реализация
  `ICodeGenerationService`; нужно выбрать провайдера, реализовать реальный вызов,
  очистку ответа от markdown/пояснений, обработку таймаутов/лимитов через поле
  `Error`, и **строго соблюдать правило ADDENDUM-01-A**: в запрос к модели идут
  только `systemPrompt` + промт игрока + `scene.html` — никогда `goal`/`hint` и
  никогда `scene.baseCss`/`validation`.
- Ограничение частоты AI-запросов по `playerId`.
- Сохранение промтов вместе с результатом как исследовательский материал.
- Переключить `ManualCodeEntry` в `false` в `appsettings.json` (фронтенд уже готов —
  логика полностью читает флаг из ответа сервера, статически ничего не зашито).

### Фаза 3 и позже
