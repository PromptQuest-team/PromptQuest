# PromptQuest — статус реализации

Дата: 2026-09-20. Реализована Фаза 1 по `SPEC.md`. Этот файл — не часть ТЗ, а рабочая памятка: что сделано, что не проверено и что нужно доделать. Вопросы тестирования/приёмки здесь не рассматриваются — только состав функциональности.

## Что сделано

- **Backend (ASP.NET Core 9, Minimal API)**: все эндпоинты раздела 12 (`/api/players`, `/api/levels`, `/api/attempts`, `/api/leaderboard/*`), ProblemDetails на ошибках, camelCase JSON.
- **Интерфейсы раздела 4.4** воспроизведены дословно (`IPlayerStore`, `IAttemptStore`, `ILevelStore`, `ILeaderboardService`, `ICodeGenerationService`), все методы асинхронные с `CancellationToken`.
- **In-memory реализации** хранилищ (`ConcurrentDictionary`), `JsonLevelStore` читает `Data/levels.json`, `ManualCodeGenerationService` — заглушка Фазы 1.
- **`ScoreCalculator`** — формула очков на сервере, сверено с примером из ТЗ (attempts=1, elapsedMs=21400 → score=957 — совпадает с разделом 12.4).
- **12 уровней** в `Data/levels.json` — все категории (css/selector/js), сцены и проверки под каждое эталонное решение из раздела 8.
- **Движок валидации** `wwwroot/sandbox/runner.js` — все 9 видов проверок, protocol `postMessage`, двойной `requestAnimationFrame`, обработка `forbiddenPatterns`, изоляция `sandbox="allow-scripts"` без `allow-same-origin`.
- **Сторожевой таймер** на родителе (`wwwroot/js/sandbox.js`) — удаляет iframe и завершает прогон по `timeoutMs`.
- **Фронтенд** — 4 экрана (никнейм, уровни, игра, лидерборд) на чистом JS (ES-модули), hash-роутинг, режим ручного ввода кода полностью управляется флагом `manualEntry` с сервера (не зашит статически).
- **Таймер уровня** на `performance.now()`, пауза по `visibilitychange`.
- Проверено вручную через `curl`: создание игрока, попытка → результат → очки → прогресс игрока → таблица лидеров (уровень и общая) — вся цепочка работает и отдаёт ожидаемые числа.
- Проверено: `.csproj` не содержит пакетов, нет LINQ к коллекциям хранилищ в `Endpoints/`/`Dtos/`, нет упоминаний EF/SQL/AI SDK/auth/Docker в коде.

## Что НЕ проверено (сделано, но не прогнано вживую)

- Живое прохождение всех 12 уровней в браузере (клики, а не только расчёт координат) — в этой сессии не было доступа ни к Chrome-расширению, ни к Node/Playwright.
- Поведение при реальном бесконечном цикле в JS-уровне (ожидается, что сработает watchdog и вкладка останется отзывчивой — основано на известном поведении Chromium с изолированными sandbox-iframe, но не запущено вживую).
- Переключение `ManualCodeEntry: false` в `appsettings.json` — логика в `play.js` полностью читает флаг с сервера, но сам факт переключения runtime не кликался.
- Адаптивная вёрстка на узких экранах — CSS написан (`@media`), но не смотрел глазами.

## Что нужно для финальной версии (не считая тестирования)

### Фаза 2 — обязательное для реального продукта

- **База данных.** Сейчас всё хранится в `ConcurrentDictionary` в памяти процесса — данные пропадают при каждом перезапуске сервера. Нужно:
  - добавить EF Core + провайдер БД (SQL Server или другой),
  - написать `SqlPlayerStore` / `SqlAttemptStore` по тем же интерфейсам `IPlayerStore` / `IAttemptStore`,
  - продумать индексы/связи для `LevelProgress` (сейчас `ICollection` без явной конфигурации EF).
- **Подключение AI API.** Сейчас `ManualCodeGenerationService` всегда возвращает пустой код — игрок вводит его руками. Нужно:
  - выбрать провайдера (в ТЗ не зафиксирован),
  - реализовать `ICodeGenerationService` поверх реального вызова модели,
  - добавить очистку ответа модели от markdown/пояснений,
  - обработать таймауты/лимиты/отказ провайдера через поле `Error` в `CodeGenerationResult` (контракт уже готов к этому),
  - переключить `ManualCodeEntry` в `false`.
- **Ограничение частоты запросов к AI по `playerId`** — иначе стоимость вызовов ничем не сдерживается.
- **Сохранение промтов вместе с результатом** — сейчас `Attempt.Prompt` есть в модели, но раз AI не подключён, содержательного промта на выходе ещё не появляется; после интеграции AI это станет исследовательским материалом.

### Фаза 3 и позже

- Серверная переверификация прохождений (сейчас доверяем результату из браузера клиента — осознанное ограничение Фазы 1).
- Уровни на компилируемых языках через изолированный judge-сервис.
- Редактор уровней для преподавателя (сейчас уровни редактируются только вручную в `Data/levels.json`).
- Режим реального времени (несколько игроков на одном уровне).
- Аналитика промтов (средняя длина, типичные ошибки формулировок).

### Прочее, за рамками ТЗ Фазы 1

- HTTPS/деплой конфигурация — хостинг в ТЗ не определён.
- Локализация (сейчас всё захардкожено на русском).
- Более дружелюбная обработка сетевых сбоев при отправке результата (в ТЗ описан только один повтор — реализовано минимально, можно улучшить UX).
