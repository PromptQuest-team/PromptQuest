# SPEC-ADDENDUM-02 — Принцип «скрытой информации»: каждый уровень обязан тестировать именно промт

Дополняет SPEC.md и SPEC-ADDENDUM-01. Не отменяет их, а формулирует общий принцип,
которому должны соответствовать вообще все уровни (не только `selector`), и даёт
конкретные правила конструирования сцен.

---

## Проблема

Обманки, добавленные по ADDENDUM-01 (миска рядом с тарелкой), решают проблему
только для **человека**, который видит картинку, но не видит разметку. Настоящий
ИИ в Фазе 2 получает не картинку, а **сырой `scene.html`**. Если различающий
признак закодирован в понятном имени (`class="plate"` против `class="bowl"`),
ИИ читает ответ прямо из имени класса — промт игрока при этом почти не имеет
значения: достаточно упомянуть «тарелки» в любой форме, и любой мало-мальски
компетентный ИИ найдёт `.plate`, как бы неточно игрок ни сформулировал промт.
Сложность за счёт визуальных обманок не переносится на ИИ — она существует только
в голове у смотрящего на скриншот человека.

## Принцип

**Правильное решение уровня не должно быть выводимо из одного только `scene.html`.**
Обязательно должна существовать информация, которую видит **только игрок**
(через `goal`/визуальную сцену), но которой **нет** в разметке в явном,
семантически понятном виде — и без передачи этой информации в промте
правильное решение недостижимо даже для сильного ИИ.

Проверочный вопрос для каждого уровня при проектировании:
> Если отдать `scene.html` этого уровня сильному ИИ вместе с расплывчатым
> промтом вроде «сделай как надо» — сможет ли оно случайно угадать решение
> просто по именам id/классов/атрибутов? Если да — уровень не годится.

## Конкретные правила конструирования сцен

1. **Идентификаторы и классы целевых/отвлекающих элементов должны быть
   семантически нейтральными** (`item-a1`, `elem-7`, `node-3f`), а не называть
   роль элемента (`plate`, `bowl`, `active-flag`). Исключение — id, нужные
   только для позиционирования, не раскрывающие критерий выбора (например,
   `#frog`/`#lily` в CSS-layout уровнях допустимы, т.к. они не участвуют в
   выборе *каких* элементов трогать — там задача про геометрию, а не про
   классификацию).
2. **Различающий признак должен быть «сырым», а не поименованным словом.**
   Вместо `class="small"` — например, конкретное числовое значение в
   нейтрально названном атрибуте: `data-size="18"` при пороге, который виден
   только в `goal` («выбери самые маленькие — меньше 20»). Вместо `class="plate"`
   vs `class="bowl"` — одинаковый нейтральный класс у всех элементов плюс
   различающий сырой атрибут (например, `data-depth="2"` у плоских,
   `data-depth="14"` у глубоких), а слово «плоская посуда» существует только
   в `goal`, который видит игрок, и должно быть переведено игроком в промте
   в конкретное числовое или структурное условие.
3. **У каждого уровня выбора должен быть путь, которым нельзя решить в лоб
   по названию.** Проверка при ревью: попробовать мысленно (или реально)
   решить уровень, представив, что промт — это одно расплывчатое слово из
   `goal` без уточнений. Если результат случайно совпадает с ожидаемым —
   сцену нужно доработать (сделать признак ещё менее «читаемым» по имени).
4. **Для JS-уровней с вычислением** — по той же логике: DOM может содержать
   исходные данные (`data-value`), но не должен содержать имя нужной операции
   в структуре разметки (например, соседний неиспользуемый элемент с похожим
   на «намёк» именем вроде `class="sum-hint"`). Операция (сумма, среднее,
   максимум и т.п.) должна быть узнаваема только из `goal`.
5. **Правило из ADDENDUM-01-A остаётся в силе и становится ещё важнее:**
   AI-вызов не получает `goal` — это единственный канал, через который
   правильная трактовка «сырых» признаков доходит до игрока, а от игрока
   через промт — до ИИ.

## Как это меняет уровни 7–12

- `sel-01-type`, `sel-02-class`: заменить семантические классы (`plate`,
  `bowl`, `small`) на нейтральные плюс сырой различающий атрибут
  (например, `data-shape-depth`), сохранив те же `expectedIds` в проверках.
- `sel-03-nth`: этот уровень устроен иначе — там признак структурный
  (чётность позиции), а не именной, поэтому он уже соответствует принципу
  и переделки не требует. Проверить только, что `<li>` не содержат
  дополнительных подсказывающих классов вроде `class="even"`.
- `js-01-sum`, `js-02-class`, `js-03-build`: проверить, что имена атрибутов
  и id не называют нужную операцию или порог напрямую; конкретные пороговые
  числа (как «10» в js-02) не должны быть считываемы из самой разметки как
  уже выделенные/помеченные — только из `goal`.

## Критерий приёмки (дополняет раздел 18 и критерии из ADDENDUM-01)

21. Ни для одного уровня категорий `selector`/`js` правильное решение не
    выводимо из `scene.html` по семантически понятным именам id/класса/атрибута
    без обращения к тексту `goal`.
22. Различающий признак между целевыми и отвлекающими элементами закодирован
    в нейтрально названном атрибуте с «сырым» значением (числом, кодом), а не
    в имени класса/id, совпадающем по смыслу со словом из `goal`.
